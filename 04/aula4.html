Indução Matemática

Primeiro e segundo princípios de indução, com exemplos aplicados a recursividade e corretude de algoritmos. (Gersting, cap. 2.2)

1. A ideia: subir uma escada infinita

Imagine uma escada infinitamente alta. Como saber que você consegue chegar a um degrau arbitrariamente alto, sem testar todos, um por um?

Duas hipóteses bastam:

  1. Você consegue alcançar o primeiro degrau.
  2. De qualquer degrau que você já alcançou, você sempre consegue ir ao próximo.

Degrau 1 alcançado, e cada degrau sempre leva ao seguinte:

O efeito dominó: as duas hipóteses juntas garantem qualquer degrau, não importa quão alto.

Trocando "degrau" por "propriedade P de um número n", essa é a indução matemática: uma técnica de demonstração para provar que algo vale para todo inteiro n a partir de um valor inicial.

2. Primeiro princípio de indução

Para provar (∀n)P(n), basta provar duas coisas:

PassoO que fazer
1. Base da induçãoProvar P(1) (a propriedade vale no primeiro caso).
2. Passo indutivoSupor P(k) verdadeira (hipótese de indução) e provar P(k+1).

A base não precisa começar em 1: pode começar em 0, 4, ou qualquer inteiro, dependendo do que a propriedade exige.

Exemplo: a árvore genealógica

Uma pessoa teve 2 filhos (geração 1); cada filho teve 2 filhos (geração 2); e assim por diante. Conjectura: a geração n tem P(n) = 2n descendentes.

Cada bolinha se ramifica em duas na geração seguinte: por isso o total dobra a cada geração.

GeraçãoDescendentes
12 = 2¹
24 = 2²
38 = 2³
Ver demonstração

Base: P(1): 2¹ = 2 descendentes. Verdade, pois a pessoa teve 2 filhos.

Hipótese de indução: P(k): a geração k tem 2k descendentes.

Cada descendente da geração k tem 2 filhos, então P(k+1) = 2 · P(k)

P(k+1) = 2 · 2k = 2k+1

Logo, P(k+1) vale, e a fórmula P(n) = 2ⁿ é válida para todo n.

A recursão em código espelha exatamente a indução: o caso base do código é a base da indução, e a chamada recursiva usando um valor menor é a hipótese de indução aplicada.

def descendentes(n):
    if n == 1:
        return 2
    return 2 * descendentes(n - 1)

for n in range(1, 6):
    print(n, descendentes(n), descendentes(n) == 2 ** n)

Como a recursão calcula descendentes(3)

Chamando com n = 3: cada chamada abre outra com n − 1 e fica esperando. O caso base devolve 2, e os valores voltam de baixo para cima dobrando em cada nível.

O caso base (n = 1) é a base da indução. A chamada descendentes(n − 1) é a hipótese de indução: confia-se que ela já devolve o valor certo, e só se prova o passo de n − 1 para n.

Exemplo: soma dos ímpares

1 + 3 + 5 + ... + (2n − 1) = n²

Ver demonstração

Base: P(1): 1 = 1². Verdade.

Hipótese: P(k): 1 + 3 + ... + (2k − 1) = k²

1 + 3 + ... + (2k − 1) + [2(k+1) − 1]

= k² + [2(k+1) − 1]

= k² + 2k + 1

= (k + 1)²

Logo, P(k+1) vale para todo n.

def soma_impares(n):
    total = 0
    for i in range(1, n + 1):
        total += 2 * i - 1
    return total

for n in range(1, 6):
    print(n, soma_impares(n), soma_impares(n) == n ** 2)

3. Segundo princípio de indução

Às vezes provar P(k+1) só a partir de P(k) não basta: é preciso usar valores bem mais atrás, não só o imediatamente anterior.

AspectoPrimeiro princípioSegundo princípio
Hipótese de induçãosupõe só P(k)supõe P(r) para todo r, 1 ≤ r ≤ k
Use quandoP(k) sozinho basta para provar P(k+1)P(k+1) depende de mais de uma posição atrás
Força da conclusãoequivalenteequivalente

Os dois princípios provam exatamente as mesmas conclusões possíveis; a escolha é só uma questão de qual hipótese é mais fácil de usar em cada problema.

Exemplo: todo inteiro ≥ 2 é primo ou produto de primos

Base da corretude de algoritmos de fatoração, usados em criptografia (veremos na aula 14).

Ver demonstração

Base: P(2): 2 é primo.

Hipótese: para todo r, 2 ≤ r ≤ k, P(r) vale (r é primo ou produto de primos).

Caso k+1 é primo: P(k+1) vale direto.

Caso k+1 não é primo: k+1 = a · b, com 2 ≤ a ≤ k e 2 ≤ b ≤ k

Pela hipótese, a e b são primos ou produtos de primos

Logo, k+1 = a · b também é produto de primos.

Repare por quê é o segundo princípio: a demonstração usa a e b, dois números que podem estar bem mais atrás que k, não só k. Só supor P(k) não bastaria.

4. Erros comuns

Uma demonstração por indução precisa dos DOIS passos.
Só a base sem o passo indutivo: nada garante ir além do primeiro caso.
Só o passo indutivo sem a base: o "efeito dominó" nunca começa a cair.
